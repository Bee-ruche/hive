# Decision log

The decisions that commit the protocol, with their reason. The most recent first. Past rows stay as written.

| Date | Decision | Why | Decided by |

| 2026-11-19 | **A project hosts the hive itself: its settings, its tasks and its state move into its own repository, and the run becomes a reusable workflow it calls.** A project holds `hive/project.json` (its settings, whose `repo` names that repository and whose `published` names its default branch, where the file is read; `tasks` is `hive/tasks.jsonl`, beside it) and `hive/tasks.jsonl` on the branch it publishes, its state on a branch of its own, `hive-state` (the same files as the state folder had), and a short `.github/workflows/hive.yml` that calls `.github/workflows/run.yml` of this repository every hour, pinned to a commit of its main. The run keeps its four jobs, their timeouts and their roles; it holds no secret, no GitHub App and no environment: each job has the project's own `GITHUB_TOKEN` (`plan` and `judge` read; `record` and `apply` write, and read the run's artifacts), and every job checks out the hive's code at the workflow's own commit, refusing any repository but `Bee-ruche/hive` and any commit its main does not hold. The plan names the commit of the published branch it read the settings at; the judging step reads them there, and the steps that write read them there once they have found the published branch still at it, or write nothing; a plan that names any other commit is not the hive's. `hive.py`'s steps are told the repository they run for (`--project owner/name`) and read the settings from the project's clone; a worker is told the project's repository, reads its settings from the project's own address and the feed from its branch `hive-state`, and clones this repository for the tool. `hive/projects/` and `hive/tasks/` leave this repository: miniz's copy is `examples/project/`, cjson's `examples/reference-project/`; the copies of the registry's two hourly runs are removed; `docs/hive-workflow.md` becomes `docs/hosting.md`. Who can change a project's settings is whoever can write its published branch. | « La ruche ne contient aucun projet en soi, c'est juste une série de règles qui permet la collaboration avec des personne/IA inconnus »: a central repository that holds every project's settings, state and keys is a project of its own. In a project's repository the settings, the tasks, the trusted accounts and the right to write are the project's, under the project's own rules, and the hive keeps the rules and the code. | Founder (« déplace l'hébergement », 19 November); builder (the change) |
| 2026-11-19 | **The judges are entirely in English from judge-v5.** Renamed under `tools/judge/`: the modules a plugin imports (`reading.py`, was `lecture.py`; `inputs.py`, was `entrees.py`) and every name in them, `isolate.sh` (was `isoler.sh`), the identifiers, messages, comments and tests, the toy project (`tools/judge/toy/`, its C code included), the folders inside the containers (`/tooling`, `/output`, `/build`, `/surveys`, `/variant`, `/inputs`, `/outputs`), the harness's list of inputs (`list`) and verification mode (`verify`), chrono's measurement keys (`user_s`, `system_s`, `wall_s`, `maxrss_kb`), the environment variables of the tests (`BEE_JUDGE_INTEGRATION`, `BEE_JUDGE_NETWORK`). The French plugin contract (`bee/juge/projet.py`), its toy and its tests are removed, and `report.py` reads English reports only; `COMMON_VERSION` is 5. The suspects' kinds are English words (`incomplete_analysis`, `forbidden_call`, `forbidden_symbol`, `bytes`, `symbol`, `defined_symbol`, `external_call`; `architecture`, `instruction`, `section`, `source` unchanged), in the judge, the hive's `SUSPECT_KINDS` and miniz's figures; the ledger's past lines keep theirs. The earlier design's reusable judge workflow (`examples/workflows/judge.yml`) and its tests are removed: the protocol calls the judge only through the hive. A project's own files take the new names when it moves to judge-v5; the reference judge's contract does not change. | The founder asked for the repository in English, and no project uses the French contract. | Founder (« Execute la traduction », 19 November); builder (the change) |
| 2026-11-19 | **The protocol's core moves out of `Bee-ruche/registre` into this repository, extracted at commit 2baa4d2.** Copied byte for byte from that commit: the hive's tool and its tests (`tools/hive/`), the judges (`tools/judge/`), the described settings (`hive/settings.json`), the two test projects' files and tasks (`hive/projects/`, `hive/tasks/`, which the tool reads there for now) and the volunteer worker's guide (`.claude/skills/bee-worker/`); the protocol's documents follow, without what belongs to the registry's earlier design. Since the copy, three tests read the workflows from `examples/workflows/`, and one test of the judge, which checked the registry's map of its move to English names with the registry's migration tools, stays in the registry. The two test projects' hourly runs keep starting from `Bee-ruche/registre`; this repository holds copies of their workflows under `examples/workflows/`, which never run here. The earlier log of decisions stays in `Bee-ruche/registre` ([docs/decisions.md](https://github.com/Bee-ruche/registre/blob/2baa4d2/docs/decisions.md)). | The founder's new vision: « Un protocole qui permet a des gens de dirige leur puissance IA dans une direction précise, vers un projet spécifique.
